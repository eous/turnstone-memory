**Both fixes shipped: PR #731 (2026-06-28) + PR #740 (2026-06-30).** History below condensed 2026-07-01 from the 6-round build log.

## The bug family (diagnosed 2026-06-27)
`_compact_messages` swapped `self.messages` for a summary IN MEMORY ONLY — never persisted, no marker/column, no durable event. `resume()` → `load_message_turns` loaded ALL rows, so a session that compacted N× reloaded its FULL pre-compaction transcript; if that exceeded the current model window (long session, OR switched to a smaller-context model), every post-resume send overflowed forever: no proactive pre-send compaction existed (triggers fired only after a *successful* call), compact-and-retry ignored `_compact_messages`'s return value (re-sent identical msgs), and the open-loop chunker bailed instead of shrinking.

**vLLM overflow status asymmetry — VERIFIED LIVE 2026-06-29 (deepseek-v4-flash, local vLLM):** the SAME context overflow returns **HTTP 400 `BadRequestError` on `/v1/chat/completions`** but **HTTP 500 `internal_error` on `/v1/messages`** (Anthropic SDK → `InternalServerError`, which was in the retryable set → retried 4× then surfaced as an opaque class name). THIS was the real cause of "can't resume an openai-compat session on an anthropic-compat model" — NOT tool-call ids (live-tested both directions; a provider-specific id IS persisted in the "neutral" Turn — a real latent neutrality gap, but not this bug). **Off-by-one = RED HERRING:** vLLM reports `(context_window − max_tokens) + 1` as the threshold-crossing value, not our true content size; no off-by-one in Turnstone budget math.

## PR #731 — persisted compaction checkpoint (squash `98372144`, 2026-06-28, NO migration)
`_source="compaction"` marker row (summary + `meta.watermark`; `save_message` already had `source`+`meta` columns); `reconstruct_turns_checkpointed` slices `[summary] + [rows id>W]` on resume, full history kept for /history/export/audit. Watermark W = max summarized **real** id (markers excluded so they don't skew the boundary); marker written after W so marker.id>W; latest-marker-wins. Markers filtered from display + search (both backends, NULL-safe) + export (`load_message_turns(checkpointed=False)`). rewind/retry rewired to `_persist_truncation` = `delete keep=max(get_compaction_floor, total−removed)` so the marker/prefix survive; storage-error sentinels skip the delete. Three review rounds (export-regression + rewind-corruption majors caught); ~34 cross-backend tests. Built in a worktree off main — NOT the other agent's `feat/task-agent-turn-ir` branch. Copilot "statement has no effect" on Protocol `...` stubs = FALSE POSITIVE.

## PR #740 — pre-send recovery companion (merged `c6e57941`, 2026-06-30)
Five coherent `core/session.py` changes, hardened across 4 max `/code-review` rounds (~30 findings remediated) + live verification against the vLLM box:
1. **Per-block-split chunker** — replaced the open-loop char-budget halving with binary subdivision (`_summarize_blocks`+`_summarize_batch`): an over-window batch splits per-block (chunking, not truncation); depth check at the TOP of the recursion (the single non-obvious correctness lynchpin — the `len(batches)==1` base case must hit it too or it recurses forever); lone-block overflow halves progressively down to a 2000-char floor; bail = `_CompactionIrreducibleError`, calm path. This CLOSED the open-loop-chunker sub-bug (previously deferred) and subsumes the chars/token-ratio problem.
2. **Status-agnostic `_is_ctx_overflow`** module free-fn (text match), single-sourced across formatter + stream-retry gates + send-loop recovery + chunker + task_agent. Phrase set is deliberately context-anchored: bare `"input tokens"`/`"too many tokens"` were dropped (false-matched 429 "input tokens per minute" rate-limits) while `"context limit"` (Anthropic) + `"maximum number of tokens"` (Gemini) are included. Follow-up `ee3a0297` on main further ensured a *recognized* rate-limit is never classified as overflow.
3. **Proactive pre-send compaction (Layer A)** — once before the send loop, gated on `_over_hard` (NOT `_compaction_owed`, whose advised-soft arm is #730's cooperative wind-down), `preserve_tail` from the last USER boundary (`_find_turn_boundaries`, not tail=1 — a trailing system nudge otherwise gets preserved instead of the user msg), generation-guarded, INSIDE the send-loop try/except. Handles the model-downgrade case where the session never compacted under the big model.
4. Overflow made **non-retryable** everywhere (deterministic error; no 4× backoff); triplicated retry gate factored → `_stop_retrying(exc,attempt,provider)`.
5. `_format_backend_error` surfaces "Context window exceeded …", gated on `name not in _BACKEND_KNOWN_EXC_NAMES` so a recognized RateLimitError with overflow-ish quota text isn't mislabeled.

**Cancellation/generation invariants (the round-3–5 bug cluster, all fixed):** pre-send compaction sat AHEAD of the loop-top `_check_cancelled(my_generation)` with event-only internal checks → an orphaned/superseded send could compact-and-swap the LIVE generation's messages. Fix: generation-aware pre-swap `_check_cancelled(my_generation)` threaded through `_do_auto_compact`/`_compact_messages` from ALL call sites. Manual `/compact` no longer resets `_cancel_event` (that DISARMED an in-flight cancel for a concurrent send); instead `send()` clears its OWN generation's event in `finally`. `GenerationCancelled` is a `BaseException` so `_compact_messages`' `except Exception` can't swallow it — the message-swap never runs on cancel.

**Synthetic-summary-turn consumers (the U2 family):** retry/rewind, the continuation-hint backward scan, AND `_generate_title` all treated the synthetic `[Conversation summary]` user turn as a real user message (retry regenerated over the summary; titles became "[Conversation summary]"). `_find_turn_boundaries` now excludes label-only turns; all three consumers fixed. **Lessons (durable):** (1) a new layer added AHEAD of an existing guard inherits none of it — it needs every generation/cancel invariant the loop body already had; (2) "fix the consumer" must sweep ALL consumers of the shared pattern, not just the ones the first finding named.
