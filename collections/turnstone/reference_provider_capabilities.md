Static capability facts (neither API exposes these — encode in ModelCapabilities, don't probe):

- **Local lanes have NO static tables (PR #774)**: openai-compatible (both surfaces — responses pin = `OpenAIResponsesProvider(compat=True)`) and anthropic-compatible return plain lane defaults for every model id; operator declares everything on the model definition. Never re-add model-id-keyed profiles for local lanes — ids are operator-chosen strings. Local effort semantics: knob forwarded VERBATIM (openai-compat flat param via `effort_passthrough`; anthropic-compat template key `effort_param` or fallback `reasoning_effort`), snap only against operator-declared values. `thinking`/`enable_thinking` = boolean toggles; `reasoning`/`reasoning_effort` = graded keys. **`finish_reason_optional` (2026-07-13, #831)**: operator-declared tolerance for servers/gateways that never send a terminal signal — armed, a clean stream end after output (content/reasoning/tool calls) completes as "stop"; default STRICT (clean signal-less end = died-mid-generation, retryable `IncompleteStreamError`) because SSE can't distinguish lax completion from clean-close truncation. Honored on ALL drained lanes (chat: no finish_reason; anthropic: no stop_reason AND no message_stop; responses: no terminal event) — was chat-only for one round; the LiteLLM-class lax-gateway scenario is anthropic-compat.

- **OpenAI effort vocabulary (verified 2026-07-04; UPDATED 2026-07-09 for GPT-5.6)**: `none/minimal/low/medium/high/xhigh/max`. **`max` NOW EXISTS** (supersedes the old "NO max" note) — introduced by **GPT-5.6 Sol** (GA 2026-07-09), the FIRST commercial OpenAI model to use it; the ordinal knob already ranked `max` for the Anthropic lane so no snap/ladder change was needed. xhigh: 5.2+/codex-max lineage. gpt-5.5 & gpt-5.6 default = **medium** (5.4 default none). **TABLE FLOOR = gpt-5.4 (pruned 2026-07-13 on `feat/transport-collapse`, the maintainer's call: o-series + pre-5.4 GPT rows unused in the field)** — removed: o1/o1-mini/o3/o3-mini/o3-pro/o4-mini, gpt-5/-mini/-nano/-pro, gpt-5.1(+codex-max), gpt-5.2(+pro), gpt-5.3; `gpt-5-search-api` + audio rows KEPT. Legacy ids resolve to `OPENAI_DEFAULT` (temperature sent, no effort vocabulary, 200K window); remediation = capabilities JSON on the model definition. Historical facts if rows return: `minimal` was original-gpt-5-family only; o-series accepted low/medium/high except o1-mini (none); codex-max needed its own row or prefix-matching lost xhigh (same hazard now pinned on gpt-5.4-pro vs gpt-5.4).
- **GPT-5.6 (onboarded 2026-07-09, `OPENAI_CAPABILITIES` in `_openai_common.py`; CORRECTED 2026-07-10)**: three tiers **Sol / Terra / Luna**; bare `gpt-5.6` alias = Sol. **`max` effort + `reasoning.mode="pro"` are on ALL THREE tiers** — the 07-09 "Sol-only" reading was wrong/stale (verified 2026-07-10: latest-model guide "Pro mode works with any GPT-5.6 model", family effort list incl. `max` with no tier restriction, SDK 2.45 types `Literal['standard','pro']` + effort literal incl. `max`; correction landed via GPT-5.6's own live-test branch `fix/openai-gpt-5.6-review`). `reasoning.mode` also accepts explicit `"standard"` (=default). All 1.05M ctx / 128k out (Luna 1.05M CONFIRMED on model card) / tool_search+vision+pdf+reasoning_replay / default effort medium / temp only at effort=none. `gpt-5.6-sol` prefix-resolves to the `gpt-5.6` row. **NO `gpt-5.6-pro` model** — "pro" is a `reasoning.mode` Responses param (contrast gpt-5.4/5.5-pro which ARE separate models).
- **Verbosity + pro-mode SHIPPED (2026-07-09, same change)** as operator-declared `ModelCapabilities` fields — NOT threaded through the shared `create_streaming` signature (Responses-specific; Anthropic/Google/xAI don't have them). New caps fields in `_protocol.py`: `supports_verbosity`+`verbosity` (value "low/medium/high"), `supports_pro_mode`+`reasoning_mode` (value "pro"). Static flags: verbosity on all 3 gpt-5.6 rows, pro-mode on Sol/alias ONLY. Operator turns them ON via the model-def **capabilities JSON** (`{"verbosity":"low"}` / `{"reasoning_mode":"pro"}`) — merges at request time via `ChatSession._resolve_capabilities` (field-filtered `dataclasses.replace`, session.py:1980); default "" = omit, so ZERO behavior change unless opted in. Wire (Responses `_build_kwargs` only): verbosity → **`text.verbosity`** (top-level 400s there — `apply_verbosity` in `_openai_common.py`); pro → folded into the reasoning dict as **`reasoning.mode`** (rides with or without effort). Goldens: `openai_responses_verbosity_pro__text.json`. Verbosity is Responses-API-only (NOT wired on the Chat/compat lane — local servers don't advertise it); to extend `supports_verbosity` to gpt-5.1–5.5 later, just flip the flag on those rows.
- **5.6 prompt caching RESOLVED (2026-07-10, branch `fix/openai-gpt-5.6-review`)**: `prompt_cache_retention` IS deprecated for 5.6+ → send `prompt_cache_options={"ttl":"30m"}` ("30m" = only supported ttl value AND the default; `mode`: implicit(default)/explicit — turnstone sends ttl only). Cache writes now BILLED at 1.25× uncached input rate; `cache_write_tokens` reported in `prompt_tokens_details` (Chat) / `input_tokens_details` (Responses) → wired into `cache_creation_tokens`. Needs `openai>=2.45` (2.44 lacks the typed `prompt_cache_options` kwarg → TypeError). Cache params also STRIPPED from local lanes (chat lane + compat-pin Responses) — a `gpt-5*` served-model name no longer injects commercial cache controls.
- **Still-unwired 5.6 surface (remaining gaps):** `reasoning.context{auto,all_turns,current_turn}`, programmatic tool calling (`allowed_callers`/`program`), "ultra" multi-agent (Sol-only, beta), image detail `original`/`auto`.
- **Anthropic effort matrix (verified 2026-07-04, platform.claude.com effort page)**: max on fable-5/mythos-5/opus-4.8/mythos-preview/opus-4.7/opus-4.6/sonnet-5/sonnet-4.6; xhigh on fable-5/mythos-5/opus-4.8/opus-4.7/sonnet-5 ONLY; opus-4.5 supports effort (low/medium/high) ALONGSIDE manual budget_tokens; haiku-4.5 no effort. API default effort = high (4.8/sonnet-5 documented). **Sonnet 5**: adaptive thinking ON by default, manual budgets 400, `thinking:{type:"disabled"}` ACCEPTED (unlike fable-5 where it 400s), sampling params rejected like 4.8/fable, thinking display "summarized" opt-in, 1M ctx/128k out. Sonnet 4.6 max output = 128k (not 64k). **Gap (re-checked 2026-07-06):** `claude-mythos-5`/`claude-mythos-preview` are real models (Mythos Preview announced 2026-03, Mythos 5 since GA per the effort page) but `_ANTHROPIC_CAPABILITIES` in `core/providers/_anthropic.py` has NO entry for either — `_lookup_capabilities`'s longest-prefix match would silently fall back to `_ANTHROPIC_DEFAULT` (no effort support at all) if either were configured as a turnstone model id. - **Fable 5.1 (onboarded 2026-09-03, branch `feat/fable-5-1-onboarding`)**: row = fable-5 row + NEW field `thinking_prefix_bound=True` (`_protocol.py`, appended after `finish_reason_optional`). - **Opus 5.5 (#1216) and Sonnet 5.5 (#1227) rows**: same recipe as Fable 5.1, the base row plus `thinking_prefix_bound=True`; Sonnet 5.5 also sets `supports_mid_conversation_system`, which Sonnet 5 lacks.
