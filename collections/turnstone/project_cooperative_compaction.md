**Bug it fixes.** Two deterministic shell maps disagreed about how full the context was. Tool-output **truncation** (`_remaining_token_budget`) used the accurate, provider-anchored size; **mid-turn compaction** used a naive `_system_tokens + sum(_msg_tokens)` that omits tool-definition tokens (resent every request) + thinking/native-lane content, so it under-counted. Result: a dead zone (~80–100%) where the model got honestly-truncated tool output but compaction never fired, so it flailed for ~20 turns until it went idle and the end-of-turn check (real `_last_usage`) finally compacted.

**Durable principle.** Truncation and compaction MUST read ONE fullness measure or they contradict. That measure is `_estimated_prompt_tokens()` = `_last_usage["prompt_tokens"]` + delta since calibration (clamped). Providers already fold cached+non-cached into `prompt_tokens` at the boundary (`_anthropic.py total_input` adds `input + cache_creation + cache_read`; OpenAI/Gemini already inclusive; streaming merge uses `max()` so message_start's full count survives message_delta's ~0). So the measure is cache-correct for free.

**Cooperative compaction = the [[project_canonical_trajectory_redesign]]/HYPOTHESIS cancellation discipline reused.** Don't preemptively collapse the tape under the model (destroys working state). `_maybe_compact_midturn` escalates: soft threshold first crossing → inject a `compaction_pending` advisory (model spills goal/remaining-tasks/next-steps onto the transcript — a register-spill before the tape collapses, which also de-lossifies the summary) and latch `_compaction_advised`; if it keeps working past the advisory OR crosses the hard ceiling (`min(0.95, pct+0.10)`) → compact. Latch `_compaction_advised` cleared at **send-entry** (per-send scope — covers cancel/error/superseded/clear/new/resume; the review caught it leaking across these), on every `_compact_messages` *attempt* (ahead of its early returns, else a bailed compaction retry-storms), and at end-of-turn. Advisory rides the existing system-turn/nudge rail (`_append_system_turn`, source in `tool_advisory.SYSTEM_TURN_SOURCES`, template in `metacognition._NUDGE_MAP`).

**Seamless wind-down (#1).** After an end-of-turn auto-compaction, if the model stopped *because it was advised* (capture latch as `stopped_to_compact` BEFORE the reset), re-prompt via `_append_user_turn(...)` (the same path a real user message takes — literally "summary as a user message") and `continue` the loop so it resumes — gated so a *natural* finish still compacts-then-idles. No two-sequential-user-turns: compaction leaves a trailing assistant (summary) turn, so the sequence is user→assistant→user (same shape as a human continuing after any compaction).

**Compact-before-truncate (#2).** `_compact_messages(preserve_tail=k)` summarizes old history but keeps the last k turns verbatim. In the tool loop, BEFORE sizing the truncation budget: if `_compaction_owed()` → `_do_auto_compact("mid-turn", preserve_tail=1)`, keeping the in-flight assistant tool-call turn so the fresh results aren't **orphaned** from their `tool_use` (the naive "compact-all before truncate" deletes the tool-call message → orphaned tool_result → provider error — the hazard the deferred sketch missed) and truncate against the *freed* budget. `_compaction_owed()` = `used > hard or (used > soft and advised)` — shared predicate, also used by `_maybe_compact_midturn`. Unified compaction action = `_do_auto_compact(where, preserve_tail)` (used `round()` not `int()` for the pct label).

**Chunked/hierarchical summary (#3, commit `bfaaab81`).** The summary call itself could overflow: it ran as ONE `_utility_completion` sized by the per-message token estimate, which disagreed with the head+tail-capped formatted text; a resumed/over-full session then 400'd on the summary call (or the old prefix-fit silently dropped the most-recent messages). Fix: `_compact_messages` summarizes the WHOLE selection via `_summarize_blocks` → `_pack_blocks` greedily packs formatted blocks into batches each ≤ `_summary_input_budget_chars()`, summarizes each, recursively merges partials (depth-0 prompt = compactor, depth>0 = merger) until one batch; base case (it all fits) stays a single call. Bail (`_CompactionIrreducibleError` → False) when a level can't shrink the count or depth ≥ 5; atomic — mid-chunk failure leaves messages untouched. Also folds tool-def tokens into the `_last_usage`-less estimate so a just-resumed session stops undercounting.

**KEYSTONE bug the max-effort `/code-review` caught (my inline review MISSED it).** `compact_max_tokens` DEFAULTS to the full window (32768 = `context_window` default; `max_output_tokens` default 64000). So `output_reserve = min(compact_max_tokens, max_output_tokens) = 32768` ate the ENTIRE window → `_summary_input_budget_chars` floored to `_MIN_SUMMARY_BUDGET_CHARS` (2000) AND `_summarize_once` requested 32768 output on a 32768 window → overflow → "Compaction failed" → never compacts at default/small-window config (the local/vLLM base). Fix = `_summary_output_tokens()` caps the reserve at `max(512, context_window // 2)`, used by BOTH the budget sizing AND the actual call's `max_tokens` (single source). Large windows unaffected (`compact_max_tokens` stays binding). Plus: empty-summary guard (`if not summary.strip(): return False` — thinking models emit empty content [[project_utility_completion_thinking_budget]]; the unguarded swap was silent TOTAL context loss while returning True); post-compaction `_last_usage` anchor now folds tool-def tokens too (symmetric with the estimate, else compact-before-truncate over-states free space); single-sourced the drifted compactor/merge prompt section (`_COMPACT_OUTPUT_FORMAT`) + tool-def sizing (`_tool_def_chars`/`_tool_def_tokens`).

**Durable testing lesson.** Both my inline review and the first implementer's tests used a SMALL `compact_max_tokens` (4000/100), which hid the default-config collision (`compact_max_tokens == context_window`). Green gates ≠ correct when the tests don't exercise the shipped DEFAULTS. Compaction/budget code needs a config-matrix test that pins the real defaults (32768/32768/64000) — `test_default_config_summary_call_fits_window` is that guard now. When a fix's correctness depends on config, test the default config explicitly.

**Also:** `auto_compact_pct` floored at 0.1 (registry `min_value` + constructor `max(0.1,…)`); the old "0 = disabled" was a lie — 0 made `> window*0` always true (compact every turn). Truncation markers were already honest (`[N chars truncated]`), so NOT a HYPOTHESIS "never none" violation — the failure was drift/shell-consistency, not fold-back honesty.
