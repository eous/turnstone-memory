## Durable architecture (don't relitigate)
- **A pane = a generic window onto any turnstone surface** (session / admin / dashboard / future tool). `PaneManager` (`shared_static/pane.js`) is the one new abstraction: keyed singleton panes, tabs, rehydrate from sessionStorage, per-type auth gates (`setAuthGate`), generic tab-action dropdown driven by a per-pane `tabMenu()` descriptor, optional binary split-layout tree (`_layout === null` = legacy single-pane bit-for-bit; visible panes = %-inset absolutely-positioned cells, NEVER reparented, so live SSE DOM/scroll/media survive).
- **Locality invariant (user, 2026-06-05):** coordinator and interactive are PEER workstream classes discriminated by WHERE they live — coordinators ALWAYS in the console process, interactive ALWAYS on a cluster node. The load-bearing pane difference is **transport**: coordinator Tier-2 SSE is console-LOCAL; interactive is node-PROXIED (`/node/{id}/…`). Shared conversational substrate is transport-agnostic; panes are parameterized by (transport-locality, affordances), never a subclass hierarchy.
- **Two-tier SSE** (enabled by Caddy h2+TLS retiring the 6-conn cap — NOT the #540 fan-in): one global Tier-1 `clusterState` stream + per-pane Tier-2 `EventSource`. **Single-writer rule: tab glyphs are Tier-1-only** (rail.js `glyph()` exported = one source, tab+rail always agree); the pane's Tier-2 stream drives its BODY, not the tab.
- **The persona choice IS the endpoint choice** — coordinator create = console-local POST, interactive create = node-proxy POST; no unified create endpoint. Storage is shared across kinds (`list_kind` filter is the only separation). Saved list is operator-gated (`admin.coordinator`) server-side AND client-side — loosening the backend gate over-exposes all users' sessions.
- **Headers were removed, not slimmed** (user redirect): name→tab+rail, state→glyphs, end/export→tab dropdown. Headers had been FUNCTIONAL mount hosts (coord wait indicator, `--skip-permissions` security banner) — the banner moved to `messagesEl`; a naive delete would have dropped a security warning.
- Interactive panes survive reload via `TS_APP.resolveInteractiveNode` (origin-first POST /open + rendezvous fallback); PaneManager persists nodeId as opaque `pane.meta`. Coordinator reload survives because it's console-local and stays warm — `/history` is a storage display-read, `/events` needs the ws in memory.
- **Tool-owned surfaces (settled):** turnstone's own = structured widget trees (no model-authored HTML) lowered into `Turn`; third-party MCP-server UI = MCP Apps / `ui://` on-ramp, deferred to #681 ([[project_1_7_roadmap]]). Trust boundary is approval + output-guard (same gate as `bash`); sandboxing is NOT a security control for self-hosted turnstone. Don't re-spike.

## House style (all frontend work)
Vanilla ES6+, programmatic DOM, **no `innerHTML`** except `renderer.js`, root-scoped `querySelector` (pane-internal; the shell orchestrator may use document ids). **ESM everywhere** — shared_static migration is COMPLETE; `theme.js` DELIBERATELY classic (FOUC) + vendor katex/hljs/mermaid classic. Interop layers one-directionally: deferred ESM reads classic `window.*` globals, classic never imports ESM. Conversational cards = the neutral `.conv-*` vocabulary on DS tokens (`--ok/--warn/--err/--ink-*/--panel/--hair`, NOT chat.css's legacy `--green/--red/--fg`); risk normalization single-sourced in `shared_static/conversation.js` (unknown→"medium", user decision). Approve=`--ok` fill / Deny=`--err`.

## Durable gotchas (hard-won)
- **Big JS surgery: use guarded Python `str.replace`/splice, NOT the Edit tool** — Edit mangles non-ASCII escapes (`\uXXXX`↔glyph) so `old_string` won't match glyph-dense code; each Python edit must assert its match count, plus a final no-stale-vocab assert (which false-positives on class names in COMMENTS — strip/update those).
- **Audit-gap pattern:** a consumer grep that excludes `const/let/var` lines misses initializers with side effects (`const _t = createSavedTable(...)` at top level = parse-time ReferenceError that kept BOTH deployments from booting; caught only by real-page load harnesses). Before declaring suites green, grep tests/ for the FILENAMES of every modified source file — static-list greps miss behavioral consumers (test_renderer_js).
- **Headless harnesses need an HTTP origin once modules import absolute `/static/...` paths** (file:// can't resolve them). Pattern: tiny static server + symlinks; `scripts/livepass.py` is the shipped descendant ([[reference_headless_chrome_frontend_render]]).
- **CSS removal:** token-diff rule-remover with word-boundary corpus match, comments stripped PER-FILETYPE (HTML only `<!-- -->` — else an `accept="text/*"` attr eats live markup); `hljs-`/`katex`/`mermaid` are runtime-built class families INVISIBLE to a literal corpus → protected-prefix gate. The markdown/syntax/math theme lives ONLY in each ui's OWN style.css — shared sheets don't carry it. `scripts/css_specificity_audit.py` is a CASCADE-FLIP checker, NOT a dead-rule remover; its console/coordinator page manifest entries were still stale pre-L-shell (pre-existing).
- **An INSET box-shadow paints in the element's own background layer** → under any opaque edge-touching child; focus rings go on a click-transparent `::after` overlay.
- Prefer a CSS **variable override** over a property override to avoid cascade flips (the `--dash-grid` 6-col standalone case).
- Dual designer review (primed + neutral cold) finds DIFFERENT things; a primed reviewer who can't act means the MAIN session is the primed seat, but the cold lens must stay a separate context. Livepass demo panes must include the chrome that collides (the coord-sidebar ↻ collision shipped because demos lacked the sidebar).
- aria-pressed on one-shot VERB buttons (split) is wrong — it announces false toggle semantics.
