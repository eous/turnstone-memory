# Messages-API provider lane (vLLM /v1/messages) — spike VERIFIED 2026-06-11

## VERIFIED — works
- Full streaming event fidelity: message_start → content_block_start/delta/stop → message_delta(stop_reason+usage) → message_stop; delta types incl. `thinking_delta`, `signature_delta`, `input_json_delta`. SDK `messages.stream()` helper path works (our provider's path).
- Thinking blocks emitted **by default** (reasoning parser), with signatures; interleaved thinking+tool_use; **parallel tool calls** in one turn (stop=tool_use).
- Tools: auto + forced `tool_choice`; tool_result round-trip; tool ids `chatcmpl-tool-*`.
- **Our provider e2e**: thinking turn, tool call, tool_result + **verbatim native replay** (`_provider_content` thinking/text/tool_use blocks accepted — even with empty/fake signature); top-level `cache_control` param tolerated; temperature forced-1.0 tolerated; usage normalized (no cache fields).
- **Mid-conversation `role:system` ACCEPTED & honored** (model switched language) — vLLM passes it to the chat template; per-model `supports_mid_conversation_system=True` opportunity (template-dependent — default False, opt-in).
- `chat_template_kwargs: {"thinking": false}` accepted as extra body field on /v1/messages **and disables reasoning** → the reasoning toggle for this lane (provider needs to forward via SDK `extra_body`; today `extra_params` only feeds budget).
- count_tokens endpoint exists (`input_tokens` + `context_management.original_input_tokens`). anthropic-version header optional; unknown top-level fields silently accepted; `metadata` accepted; consecutive same-role accepted; system as string or blocks (+`cache_control` blocks) accepted.

## VERIFIED — quirks/gaps
- `thinking` param: **not in vLLM's request schema at all** — verified in source at the running commit (2c9c07c85) AND upstream main: `AnthropicMessagesRequest` has no `thinking` field, serving code never reads one; the param is silently dropped at parse (lenient extra fields). NOT a server-side-default masking effect (user hypothesized their thinking-on-by-default CLI flag; ruled out). `chat_template_kwargs` is a **first-class field** on the Anthropic request model (intended mechanism, not leniency); serving layer has `default_chat_template_kwargs` (CLI default) and request-level keys win (verified empirically: request `{"thinking": false}` disabled reasoning on a thinking-on-default server).
- **stop_sequences**: honored as a raw-stream cut **including inside thinking** (cut mid-reasoning), reported as `end_turn` with `stop_sequence=None` — footgun, never attribute.
- Forced tool_choice returned stop_reason=end_turn despite tool_use block (quirk); auto tool call correctly stop=tool_use.
- usage = input/output tokens only — **no cache_read/creation fields** even on prefix-cache hits.
- Images: protocol accepts block; non-multimodal model → **500** `internal_error` ("not a multimodal model"), not 400.
- Two error envelopes: pydantic validation = `{"error":{"message":...}}`; runtime = Anthropic-style `{"type":"error","error":{...}}` (404 bad model). SDK maps both fine.
- missing max_tokens → 400 (required, like Anthropic).
- **NEGATIVE PROOF**: stock `_ANTHROPIC_DEFAULT` caps + a `web_search` tool → provider injects `{"type":"web_search_20250305"}` → vLLM 400 `tools.0.input_schema Field required`. Wrong-defaults blocker demonstrated.
