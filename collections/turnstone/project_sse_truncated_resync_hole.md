**MECHANISM 5 (found 2026-07-20 by the new e2e harness's first real-browser run; verified in source; FIXED in PR #887):** all three clients capture the SSE cursor off the EventSource OBJECT — `interactive.js:1378` `this.evtSource.lastEventId`, `coordinator.js:2669` `evtSource.lastEventId`, `ui/static/app.js:1776` `globalEvtSource.lastEventId` — but WHATWG puts `lastEventId` on the **MessageEvent** (`e.lastEventId`; the same files use the correct form for the `_event_id` dedup tag one paragraph later). EventSource exposes only url/withCredentials/readyState ⇒ the property is `undefined` in every real browser ⇒ all three captures are dead conditionals. Consequence: `_lastEventId` is only ever set by /history cursor seeding, so EVERY MANUAL reconnect (close-on-hide show edge, degraded-ladder retry, recover beat) presents no cursor ⇒ fresh connect ⇒ committed turns during the gap never repaint (fresh connect does not refetch history) ⇒ THE cleanest explanation of the "turn disappeared, never healed" field reports — no rehydrate needed, any hide across a busy window suffices. Native auto-reconnects are unaffected (browser-internal header). Blast radius: fix-2's truncated honesty never fires for hidden-tab restarts until this is fixed (no cursor presented); fix-1's `_truncatedFromCursor` records null on those paths. Tier-1 harness passes because BrowserlikeSSEClient implements the INTENDED contract; source-pattern JS tests can never catch it. Fix shape: read `e.lastEventId` in the three onmessage handlers (guard `!== ""` — MessageEvent.lastEventId is always a string, and id "0" is valid: the error-surface snap_seq can be 0); then Tier-2 scenario B can assert the truncated envelope (the harness builder's unclosed edge closes).

Four interlocking mechanisms behind the 2026-07 "jank"/SSE-gap reports (multiple field reports + the maintainer's 5-parallel-task_agent local repro). All code-read confirmed 2026-07-20; fixes 1-3 shipped on the branch (below).

**1. Storm trigger — `tool_output_chunk` is unbatched.** `on_tool_output_chunk` enqueues one SSE event per output LINE (`session_ui_base.py` ~3096; per-line caller `session.py` ~14880). Token batching (25ms window, ~40 ev/s) covers only content/reasoning. 4-5 concurrent task_agents running chatty streaming tools ⇒ hundreds-thousands ev/s. Amplifier: every non-token `_enqueue` force-flushes the pending token batch (`_enqueue` head), so chunk storms also defeat token batching. Drain side is one-executor-hop-per-event in `make_events_handler`'s live loop ⇒ per-stream throughput ceiling; 500-cap `_ListenerQueue` poisons ⇒ `stream_overflow` close ⇒ reconnect. 3 closes/60s trips degraded catch-up (15s→120s cooldown ladder, `shared_static/sse_overflow.js`). Ring = 50k events (`_EVENT_BUFFER_MAX`) — a 15-120s cooldown under chunk-storm load evicts past the client cursor ⇒ next reconnect is `truncated`.

**2. THE HOLE — truncated resync × `_resume_cursor_and_trim`.** Client `replay_truncated` handler (interactive.js ~2093): if streaming refs null (true during tool execution — dominant wall-clock in agent turns; refs null from `stream_end` until next segment) it refetches `/history` IMMEDIATELY with `seedCursor=false`, i.e. it ignores `data.cursor` and never rewinds `_lastEventId`. Server `_resume_cursor_and_trim` (session_routes.py ~3315) TRIMS the trailing executing in-flight turn from /history whenever `can_replay_from(resolved-boundary)` — it assumes the caller will open SSE from the returned cursor (#616 fresh-connect contract). The resync caller violates that assumption ⇒ rebuild wipes the in-flight turn (task_agent parent rows, tool rows, streamed content) with NO redelivery path (events below `_lastEventId`, cursor discarded, no full-turn re-render at commit). Permanent in-session hole. Deferred branch (refs non-null → resync at idle edge) is safe — heals at `state_change idle`. So outcome is a coin-flip on WHERE in the turn the truncated reconnect lands ⇒ matches "sometimes recovers, sometimes never".

**3. The escape — orphan grace.** `_routeAgentItems` needs the parent row in DOM; missing ⇒ `_bufferAgentOrphan` (cap 256) with 500ms grace ⇒ `_escapeAgentOrphans` renders children TOP-LEVEL; `approve` mode escapes immediately (must stay visible). After mechanism-2 wipes parent rows mid-run, still-streaming children escape into the main thread. Also `_clearAgentTracking` (any rebuild) silently DROPS buffered orphans.

**4. Silent gap after evict/rehydrate — empty ring ⇒ `replay_ok`.** `register_listener_with_replay` returns `replay_ok` with zero events on an EMPTY buffer regardless of cursor (documented cold-start choice; "can't distinguish without a highest_evicted_id tracker"). A ws evicted/rehydrated (or node restarted) while a tab was hidden reconnects into a fresh UI instance (ring empty, `_seed_event_id_from_storage` prevents id collisions only) ⇒ no `replay_truncated`, no resync ⇒ missing final turns + missed `state_change idle` (stuck-busy pane). replay_ok skips the synthetic state_change. Likely THE field-report mechanism (no task_agents required). Note app.js's 404→list-reassign path heals via full reload; the silent path is when the ws rehydrates before the events connect.

Secondary: `in_progress_snapshot` guard `contentBuffer.length < evt.content.length` (interactive.js ~1793) is meaningless across turn boundaries when stale refs survive hide/show ⇒ dropped prefix + two turns merged in one bubble (transient; heals at idle resync). Coordinator.js needs parity audit (historically never read `hist.cursor`).
