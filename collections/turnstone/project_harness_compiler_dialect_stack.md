The turnstone harness is being reframed as a **compiler / control loop around `x ← f(x;W)`** — north-star design note **#700** ("Harness as a progressively-lowered dialect stack / MLIR meta-architecture"). It already *is* a compiler backend at the bottom: canonical neutral `Turn` IR → `core/lowering.py` deterministic-total passes (`fold`/`drop_empty`/`repair_wire_messages`, where `repair` = an MLIR legalizer) → `C`-layer provider translators (codegen). See [[project_canonical_trajectory_redesign]].

**Dividend + limit:** borrow *how* LLVM/MLIR is built, NOT *why* it's correct — every guarantee there rests on a formal source semantics NL lacks; that missing semantics is the *same root cause* as the missing agentic-loop convergence guarantee (NL = "all undefined behavior"). So copy **MLIR's** meta-architecture (dialects + progressive lowering + self-authored per-level verifiers), not LLVM's.

**Keystone:** **dialect-depth = soundness = which-side-of-the-gate.** Decidable/sound transforms at the bottom (wire passes; bijective rename #698) ship free; speculative ones at the stochastic top (intent↔meaning frontier) sit behind a *measured* gate — the same line as output-alignment's "soundness ⇒ free, speculation ⇒ proof" (epic **#689**, the first concrete pass within the frame; sub-issues #690–#698; #690 = the harness's PGO; #695 = MLGO/learned pass-ordering).

**Three states of the stack:** *Built* — the decoupling (`Turn` waist collapses M providers, N+M). *Unsettled (**#699**)* — the wire IR's *level*: the `native`/`provider_data` lane is the **leak** (an IR needing an opaque side-lane to round-trip is over-lowered); mine the convergent native block protocols (Anthropic Messages blocks / OpenAI Responses items) for a richer **neutral block dialect** + provider dialects below, shrinking the lane to the truly-private. *Proposed (up the stack)* — explicit **intent** / **plan** dialects with authored verifiers (today `plan_agent`/`task_agent` output is in-context content, not a typed IR level).

**Why:** the lens is a *sorting function* — predicts which harness work is cheap-and-safe (decidable → ship) vs. needs proof (stochastic → gate), names the one guarantee you can never port (lattice/fixpoint termination — no lattice/monotonicity/Lyapunov over `f`; the refine-retry loop ≈ LLVM's heuristic *pipeline*, NOT its dataflow *fixpoint*), and gives the engineering substitute (hard iteration budget + forced-progress metric, already practiced: judge-deadline daemon #674, output-guard budget loop, coord `wait` fail-fast).

**Formal object** (HYPOTHESIS.md / PR #703; README headline equation): the harness *is* a **stopped, deterministically-controlled Markov chain on task-state, closed around a stopped autoregressive chain on context-space** — a deterministic **controller** (`π, ρ`, halt, readout; injects no randomness of its own) in closed loop with a stochastic learned **plant** (`M_W` + env `E`); the arc `f(x) → x=f(x;W) → f(x)` is the controller re-imposing the determinism the model dissolved. The unportable guarantee has a name — **Foster–Lyapunov descent**: the minimal `V` is *forced* to be the expected halting time `V*(s)=E[τ*|s]`, which **exists but doesn't compress below model scale** (not absent — *incompressible*; the compiler's `V` is structurally trivial, ours is as hard as the dynamics). You never compute it; you measure a candidate's **drift-slack `δ`** (the concrete #690 metric): `δ≤0` ⇒ a conservative halting certificate, `δ>0` ⇒ a measurable non-halting radius; floors `μ(D)` + heavy-tailed `Var[τ*]`. This made the frame exact: `r = r_shell + r_plant` (shell = the monotone-narrowing descent), #693 recast injection as *adversarial `E` → minimax drift* (`ρ`/output-guard = the disturbance-rejection margin; **security = robustness of the certificate**), #695 = MLGO with `δ` as the reward. Coordinators/daemons flip halting → **recurrence-to-ready** (positive Harris recurrence). See [[project_judge_deadline_daemon]] (the budget+forced-progress termination guard) and [[project_three_facet_validation]] (`ρ` = the output-guard verifier). Citations + proven-vs-asserted grounding: [[reference_harness_formalism_grounding]].

**How to apply:** (1) draw dialect boundaries at **verifier-decidability transitions**; put the gate at the first level whose verifier can't be decidable (where the coin enters). (2) Design each lowering to **narrow variety monotonically** — the only termination-ish guarantee, *designable not provable*, enforceable-by-construction at the bottom, only measurable at the top. (3) Don't hunt a perfect static pass order (phase-ordering known-lost; heuristics/learned). (4) Verification transfers in *form* (validate every boundary, fail closed, no malformed IR downstream) but not in *teeth* (no source standard). Reach for this when sequencing/justifying harness work or deciding whether a transform needs the measurement gate. Related: [[project_1_7_roadmap]].
