**#894 shipped via PR #899 (2026-07-24, branch `fix/894-coord-over-rewind`; the numbers are pointers — status is gh's job).** The issue's two-comment checklist (the #890 port: latch-not-flag, quiesce-free retry, TRANSPORT-FREE backstop, teardown wiring, storm-assertion validation) shipped as specced, but review r4 found the seam under it unguarded and the campaign tripled: 10 rounds, 6 fix-eras, and a the maintainer-approved server expansion.

**Final design (coordinator.js):** `historyStale` latch (set at clear_ui, cleared ONLY in refetchHistory's success path) gating `_rewindToMessage`/`_editAndResend`/`_startEdit` via `busy || historyStale`; one bounded teardown+OPEN-stream-gated 2s retry + the transport-free idle-edge backstop; `refetchesInFlight` depth counter + `refetchSeq` dispatch stamp; the /history await bounded (AbortController 15s; destroy aborts a SET of in-flight controllers); RENDER-TIME gate post-await pre-wipe — universal: seq + content refs; seedless-only: `liveToolCalls` + optimistic `busySource` + stream-OPENness. **Server:** `ChatSession._history_generation` bumped in `_persist_truncation` AFTER the delete; the #884 flight key is `(ws_id, limit, generation)`, cold workstreams key on `None`, typed access.

**The liveness-predicate ladder (the campaign's core lesson).** Three encodings of "this DOM holds live turn state" failed in sequence before the fourth held: plain `busy` (r5 critical — busy means EXECUTING, not DOM-live; `_editAndResend` flips busy pre-POST and /rewind emits no state_change, so the truncation render itself was skipped); `activeBatch` (the pending-APPROVAL tracker, not an executing marker); the `.conv-batch--running` DOM class (r6 — forgeable: the render's own orphan repaint carries it and nothing strips a dead orphan's). The held encoding: an EVENT-DRIVEN set fed only by live announces, retired by results/settle-edges/pane-death — **liveness must be read from the channel that creates the hazard, never from state the render path can rewrite.** Retirement r7: transport death is NOT retirement (the reconnect replay does not re-announce — verified; a stale id fails CLOSED, an emptied set fails OPEN).

**The joined-flight lesson (r8).** Client dispatch stamps cannot see SERVER-side staleness: a post-rewind dispatch joining a pre-rewind #884 flight carries a current stamp with stale bytes. Freshness across a coalescing seam needs a key component owned by the mutator (the truncation generation). The r8 client-side epoch guard was proven UNREACHABLE in r9 (clear_ui always dispatches immediately, so stale-epoch ⟹ stale-seq) and removed — **check a guard's reachability before shipping it; a redundant guard is misdirection for the next reader.** Fail-direction discipline throughout: bump-after-delete, None-for-cold, stale-fails-closed.

**Harness honesty (two false detectors caught).** G7 v1 held flights via `delay_history` — which sleeps in the FAULT layer, before the route, where flights never overlap; its negative control passed vacuously. G7 v2's first counters used `history_requests` — HTTP arrivals, also the wrong layer. The rebuilt detector (`delay_load` sleeping INSIDE `load_messages`, post-load so a held flight holds the rows it read; `load_calls` join/miss counting, lock-guarded — to_thread writers) immediately caught a REAL bug in the server fix (mgr.get returns the Workstream WRAPPER; a stringly getattr defaulted the generation to 0 forever while the unit mock mirrored the same wrong shape). **Hold and observe at the same layer as the mechanism; typed access so mypy carries invariants; mocks must pin the real nested shape.** Scenario family: C + G1-G7 in scripts/recovery_e2e.py, every one negative-controlled (posts2-rows0 / closed2-heal0 / sse1 / hist1 / hidden1 / orphan1 / loads1-rows3).
